# Bybit → Telegram: бот-уведомитель о выводах

Бот раз в N секунд опрашивает Bybit API (эндпоинт «история выводов») по
каждому из ваших аккаунтов и присылает сообщение в Telegram, как только
появляется новый вывод средств.

## 1. Создать Telegram-бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте имя и username.
3. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxx` —
   это `TELEGRAM_BOT_TOKEN`.

## 2. Создать API-ключи Bybit (только чтение!)

Для каждого из 5 аккаунтов:

1. Зайдите в аккаунт на Bybit → **API Management** → **Create New Key**.
2. Тип — **System-generated API Key**.
3. Права: включите только **Read-Only** (чтение). **Не выдавайте права на
   торговлю и вывод средств** — боту это не нужно, а ключ на вывод — большой
   риск, если он утечёт.
4. Если Bybit требует привязку по IP — либо оставьте без ограничения по IP,
   либо привяжите статический IP вашего сервера (на Railway IP не
   статический, поэтому обычно проще оставить без привязки, раз ключ
   read-only).
5. Сохраните `API Key` и `API Secret` — они понадобятся в переменных
   `BYBIT_API_KEY_1` / `BYBIT_API_SECRET_1` и т.д.

## 3. Настроить переменные окружения

Скопируйте `.env.example` в `.env` (для локального запуска) или задайте те
же переменные в настройках хостинга (Railway → Variables):

- `TELEGRAM_BOT_TOKEN` — токен из шага 1.
- `TELEGRAM_CHAT_ID` — можно оставить пустым: после первого запуска
  отправьте боту `/start` в Telegram, он запомнит чат. Чтобы значение не
  сбрасывалось при перезапуске, лучше узнать свой chat_id (например через
  [@userinfobot](https://t.me/userinfobot)) и прописать его явно.
- `BYBIT_API_KEY_1..5`, `BYBIT_API_SECRET_1..5`, `ACCOUNT_1..5_NAME` — данные
  по каждому из 5 аккаунтов. Если аккаунтов меньше пяти — просто не
  заполняйте лишние номера.
- `POLL_INTERVAL_SECONDS` — как часто проверять (по умолчанию 60 секунд).
- `STATE_FILE` — путь к файлу, где бот хранит список уже отправленных
  уведомлений (чтобы не дублировать их после перезапуска).

## 4. Деплой на Railway

1. Создайте новый проект на [railway.app](https://railway.app), подключите
   этот код (через GitHub-репозиторий или `railway up` из папки проекта).
2. В настройках сервиса добавьте все переменные окружения из шага 3
   (Variables → Raw Editor удобно вставить сразу все).
3. **Важно про сохранение состояния:** без Volume файловая система Railway
   не сохраняется между деплоями/рестартами, и при каждом перезапуске бот
   заново разошлёт «первые» найденные выводы как новые (на первом запуске он
   их просто запоминает и не шлёт, но каждый передеплой = новый «первый
   запуск» без Volume). Чтобы это исправить:
   - В Railway откройте сервис → **Volumes** → **New Volume**.
   - Примонтируйте его, например, на `/data`.
   - Убедитесь, что `STATE_FILE=/data/state.json`.
4. Деплой запустится автоматически. Проверьте логи — там должно быть видно
   количество настроенных аккаунтов.
5. Отправьте боту в Telegram `/start` — он подтвердит, что чат подключён, и
   покажет список отслеживаемых аккаунтов. Команда `/status` показывает
   текущие настройки.

## Как это работает

- Бот вызывает эндпоинт Bybit `GET /v5/asset/withdraw/query-record` с
  подписью запроса (HMAC-SHA256 по API secret), для каждого аккаунта
  отдельно.
- При первом запуске (или после сброса состояния) бот запоминает уже
  существующие записи, чтобы не заваливать вас историей старых выводов —
  уведомления приходят только по новым записям, появившимся после запуска.
- Список уже увиденных `withdrawId` сохраняется в `STATE_FILE`, чтобы при
  перезапуске бот не разослал старые уведомления повторно.
- В сообщении указаны: сумма, монета, сеть, статус, адрес получателя,
  время, ID вывода и TxID (если уже присвоен).

## Локальный запуск (для проверки)

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполните значения
export $(grep -v '^#' .env | xargs)  # или используйте python-dotenv
python main.py
```

## Безопасность

- Используйте **только** read-only API-ключи Bybit.
- Никогда не публикуйте `.env` или переменные окружения с ключами.
- `TELEGRAM_BOT_TOKEN` тоже даёт полный доступ к боту — храните его в
  секрете (переменные окружения Railway, а не в коде).
